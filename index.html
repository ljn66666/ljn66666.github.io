Three failures I have actually hit

On real hardware, not from a tutorial.

Board reboots every time the servos move
Four SG90s starting together pulled roughly 900 mA from the board's USB rail. The rail sagged below the brownout threshold and the chip reset.
Fix: separate 5 V supply, common ground, 470 µF at the servo rail, and sequential moves with a 150 ms gap. No firmware change alone would ever fix it.
Analog input reads 0 as soon as Wi-Fi connects
The pin was on ADC2, which shares hardware with the radio on ESP32. While Wi-Fi is running, ADC2 returns invalid values and raises no error at all.
Fix: move the input to an ADC1 pin. Code review will never find this.
Servos twitch with nothing in the code
A timer channel conflict between the servo library and the LEDC channel driving a buzzer.
Fix: reassign the LEDC channel and verify the timer group in use.
